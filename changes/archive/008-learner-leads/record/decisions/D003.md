## Question
The proposal's edge-case row says "a key with no notes in range: the start circle does nothing in either mode, as ▶ does today". That is false for play along: with an empty run `Session.start()` begins a count-in (`countingIn 4`, clicks posted); only the I lead branch (`startLead`) has the `sequence.length === 0` guard. Guard play along too, correct the row, or leave it?

## Options
- **A** — Add `if (sequence.length === 0) return;` to play along's `start()` plus the withheld test — both modes match the approved row; one line of product code in a shared start path.
- **B** — Correct the proposal row to "in I lead" — the approved text then matches the code, but the user's approved "either mode" is narrowed and a quiet bad state (a count-in over nothing, wake lock, an endless silent run) stays in code we have just seen.
- **C** — Do nothing, note it — the proposal and the code disagree at converge, and the audit has to read it as a gap.

## Judgement
- **Reversal cost:** One line and one test; deleting them is minutes. A wording amendment (B) would be as cheap, so cost does not separate the options.
- **Foundation:** Nothing is built on an empty-run start. The state is unreachable with the built-in catalogue (every catalogued variant yields a non-empty run for every key; 005's notes record the same), and I found no test or spec scenario that starts play along on an empty run: `sessionWithEmptyRun` is used only by lead-run.test.ts (REQ-015/S8) and the withheld test, and `specs/practice/session.md` has no requirement for it.
- **Reach:** Contained to `src/practice/domain/session.ts` inside the practice context; the guard sits after the tuner and lead branches, so the tuner refusal, `startLead` and every non-empty play-along start are unchanged. It does not touch the UI, listening or sound.
- **Promise:** The user approved the row "does nothing in either mode". The guard keeps that promise; option B would quietly shrink it. The reason they wrote "as ▶ does today" was a belief about current behaviour, and what they want is the behaviour. Constitution Article VI (no surprises, no demanded interaction) agrees: a count-in over nothing is the surprise the row exists to prevent. This is not an invented requirement, since the requirement is already in the approved proposal; it is not a new feature either, only the row made true.

## Verdict
DECIDED: Option A — the user approved "nothing happens in either mode" and the fix is one guard line in code that cannot be reached today, so make the code match the approved row rather than narrow the row.
