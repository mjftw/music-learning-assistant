## Question

Is this a test-authoring fix, or does the reducer or the scenario wording need to change?

- **C** — Leave the tests as given — the task cannot complete; not viable.

## Judgement
- **Reversal cost:** Two assertions in one test file and one qualifying clause in a scenario; undoing either is minutes, not an afternoon.
- **Foundation:** Nothing is built on the shape of these assertions. The reducer (which later tasks T007, T010, T011 do build on) is left exactly as approved and committed.
- **Reach:** Contained to `tests/practice/scenarios/lead-hold.test.ts` and the wording of one scenario in this change's own delta; no other context, no published contract, no stored data.
- **Promise:** The SHALL text of REQ-016 is unchanged and the reducer implements it literally; the T002 reducer test for S4 (10 ms ideal steps from t = 0) already proves "900 held, silence, 350 more" holds exactly on an ideal clock. What the session test exposes is the ±one-reading-interval quantisation the user has already accepted in REQ-021/S1 ("±one reading interval") and in the tasks-gate amendment that corrected S3 and S9 for the same discretisation. Qualifying S4's "350 ms after" by the reading interval tells the truth about how the promise is kept; it does not change what is promised.
